# Sprint 1E — VentureLab

**Status:** Complete  
**Purpose:** Decision-making and venture validation. Given a brief + personas (+ optional buying-committee transcript), emit a single auditable `VentureRecommendation` answering: **Proceed, Pivot, or Kill?**

## Hard rule (re-stated)

> Recommendation must NOT be pure LLM output.  
> Combine: **rule engine + evidence extraction + structured scoring + confidence calibration**.  
> Recommendation must be **deterministic and explainable**.

## Architecture

```
brief + personas (+ committee)
        │
        ▼
 ┌──────────────────────────┐    ┌──────────────────────────┐
 │  LLM call #1: signals    │    │  LLM call #2: assumptions│
 │  (evidence extraction)   │    │  (assumption mapping)    │
 └──────────┬───────────────┘    └────────────┬─────────────┘
            │                                 │
            ▼                                 ▼
 ┌──────────────────────────────────────────────────────────┐
 │ DETERMINISTIC PIPELINE — no LLM beyond this line         │
 │                                                          │
 │   8 analyzers → 8 VentureScores                          │
 │   ├─ problemStrength, buyerUrgency, willingnessToPay     │
 │   ├─ differentiation, marketClarity                      │
 │   ├─ adoptionFriction (higherIsBetter=false)             │
 │   ├─ committeeConfidence (pure-deterministic from        │
 │   │   deliberation: consensus × confidence − unresolved) │
 │   └─ executionRisk (higherIsBetter=false)                │
 │                                                          │
 │   computeOverallScore (weighted, inverts friction/risk)  │
 │   computeConfidenceScore (coverage × consistency)        │
 │   decide() rule engine → PROCEED | PIVOT | KILL          │
 │   generateRiskRegister(...)                              │
 │   generateNextSteps(...) — prioritised validation roadmap│
 └──────────────────────────────────────────────────────────┘
            │
            ▼
   VentureRecommendation
```

The orchestrator (`VentureLab.analyze`) makes **exactly two LLM calls** — both restricted to extraction tasks. The LLM is explicitly forbidden from producing a recommendation, decision, or overall score. Every decision rationale line is generated by the rule engine.

## Decision rules (excerpt — see `decision.ts` for source of truth)

**KILL** is triggered by any of:
- `problemStrength < 35`
- `buyerUrgency < 25`
- `committeeConfidence < 25`
- `adoptionFriction > 80 AND willingnessToPay < 40`
- `executionRisk > 85`

**PROCEED** requires **all** of:
- `overallScore ≥ 68`
- `committeeConfidence ≥ 60`
- `executionRisk < 65`
- `problemStrength ≥ 50`
- `buyerUrgency ≥ 40`
- `willingnessToPay ≥ 45`

**PIVOT** is the default when neither condition set holds. Each fired rule appends one plain-English line to `decisionRationale`.

## Weights (composite score)

| Dimension | Weight |
| --- | --- |
| problemStrength | 0.20 |
| willingnessToPay | 0.20 |
| buyerUrgency | 0.15 |
| committeeConfidence | 0.15 |
| differentiation | 0.10 |
| adoptionFriction (inverted) | 0.075 |
| executionRisk (inverted) | 0.075 |
| marketClarity | 0.05 |

Friction/risk are inverted before weighting (`100 − score`) so higher composite always means "better venture".

## Web surface

- `apps/web/src/lib/venturelab.ts` — BYOK-bound runner. Decrypted secret stays inside `CredentialService.withDecryptedSecret` callback; never reaches the browser.
- `apps/web/src/app/api/venturelab/route.ts` — POST `/api/venturelab`. `runtime='nodejs'`, `dynamic='force-dynamic'`. Validates `providerCredentialId`, `modelId`, `payload.{ventureId, brief, personas}`. Sanitises errors (`sk-***`, `Bearer ***`, 500-char cap).
- `apps/web/src/app/labs/venture/page.tsx` — Full UI: provider picker, brief editor, personas/committee JSON paste, recommendation view (decision badge, scorecard with friction/risk visually inverted, decision-rationale ordered list, two-column evidence vs counter-signals, assumption table, risk register, priority-tagged validation roadmap).
