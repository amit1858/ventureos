# Demo Mode

Demo Mode is a parallel surface that lets anyone experience the full VentureOS pipeline **without any API keys**, Supabase, GitHub PAT or network calls to providers.

## What it is

- **URL:** `/demo` (index) and `/demo/faceless-crm` (the seeded venture).
- **Scenario:** "Faceless CRM for SMB" — an opinionated sales-ops product for small business.
- **What's seeded:** Venture, 5 personas, full buying-committee deliberation, research graph with god-nodes and contradictions, VentureLab recommendation (Proceed with confidence), full BuildSquad pack, evaluation report, simulated GitHub export, timeline.

## What it is **not**

- It does **not** call any provider. No OpenAI, Anthropic, Gemini, Azure OpenAI, Supabase or GitHub call is made from a demo page.
- It does **not** require any environment variable.
- It does **not** mutate state. The seeded venture is read-only.

## Where the data lives

```
apps/web/src/lib/demo/
  faceless-crm.ts         # the seeded venture + personas + committee + graph + recommendation + pack
  render.ts               # buildDemoEvaluation, buildDemoExportFiles — reuse Real-Mode renderers
  index.ts                # listDemoVentures, getDemoVenture
```

The export file list shown in the demo's "GitHub export (simulated)" section is generated by `buildDemoExportFiles`, which calls the **same** `renderRepoScaffold` used in Real Mode. What you see in the demo is what your Real-Mode venture would look like.

## UI affordances

- A **Demo Mode banner** is pinned at the top of every demo page: `Demo Mode — seeded data, no API keys used.`
- An **Agent Swarms framing strip** below the banner names the agent groups so judges can read the page through that lens.
- A **footer note** at the bottom of every demo venture: `This is a seeded demo. Real Mode uses BYOK and real GitHub export.`
- A `Switch to Real Mode (BYOK) →` link inside the banner.

## Why it exists

1. **Submission reviewers** can experience the product in 60 seconds without needing to set anything up.
2. **Teammates** can preview workflow changes without burning provider tokens.
3. **The renderers themselves are testable** — Demo Mode is a continuous smoke-test of the public output surface.

## How Demo Mode and Real Mode share code

| Concern | Shared? | Notes |
|---|---|---|
| Renderers (PRD, vision, evaluation, scaffold) | ✅ Shared | `renderRepoScaffold`, `EvaluationReport` renderer, all markdown templates. |
| Contracts (`@ventureos/contracts`) | ✅ Shared | The seed fixtures conform to the same schemas Real Mode produces. |
| Workspace components | Partially | The demo `Walkthrough.tsx` reuses badges, rings and cards but is its own page. |
| Job orchestrator | ❌ Not used | Demo Mode is pure data; no `VentureJob` runs. |
| Credential store | ❌ Not used | Demo Mode does not touch BYOK. |
| GitHub adapter | ❌ Not used | The "simulated export" only renders files; it never calls Octokit. |

## Running it

```powershell
corepack pnpm install
corepack pnpm --filter "@ventureos/web" dev
# open http://localhost:3000/demo/faceless-crm
```

That's it. No `.env.local` required.

## Extending Demo Mode

To add another seeded venture:

1. Drop a new fixture in `apps/web/src/lib/demo/<slug>.ts`. Mirror the shape of `faceless-crm.ts`.
2. Register it in `apps/web/src/lib/demo/index.ts`.
3. The dynamic route `/demo/[slug]` will pick it up automatically; `generateStaticParams` enumerates all registered slugs.

Keep fixtures intentionally small but realistic — Demo Mode's value is "you can read every artifact end-to-end in 3 minutes."
